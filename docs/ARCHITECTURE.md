The world (lobby, stations, props) and every ScreenGui are generated by code. `StarterGui` and `Workspace` stay empty in the source, so there is one source of truth and no binary diffs.

## Battle model

* **World.luau** is a pure 2D fixed-step (60 Hz) simulation with its own seeded PRNG.
  * It applies gravity and wall reflection with a tiny deterministic jitter.
  * Ball-vs-ball collisions are mass-weighted elastic impulses. Frozen or snared balls behave as immovable.
  * An energy governor restores each orb's cruise energy, so fights stay lively without looking like constant-speed billiards.
  * Contact damage has a per-pair cooldown. Entities (hazards, projectiles, beams, trains) have circle, segment or custom collision.
* **Damage.luau** is the only damage path. It handles immunity, phasing, friendly fire, overtime multiplier, frozen vulnerability, ability modifiers, events and deaths.
* **Ability hooks**: `Init`, `OnLaunch`, `OnTick`, `OnWallHit`, `OnBallHit`, `ModifyContact`, `OnDamageTaken`, `OnDamageDealt`, `OnHealthChanged` (HP thresholds), `OnDeath` (can spawn minions or prevent death) and `OnKill`.
  * Hooks are wrapped in `pcall`, so a faulty ability is logged once and cannot crash a match.
  * The World doubles as the ability context and exposes `Damage`, `Heal`, `Spawn`, `Remove`, `Fx`, `SetStatus`, `Nearest`, `Enemies`, `SpawnMinion` and so on.
* **Adding an orb**: add an entry in `BallDefinitions.luau`. Optionally add `Battle/Abilities/<id>.luau`, and an emblem painter in `OrbArt.luau` if it needs new art. The match loop is never touched.
* **Match.luau** is the shared state machine for 1v1 and 2v2:

  ```
  MatchIntro -> RoundStart -> BallSelection -> AimPhase -> Countdown -> Battling
             -> RoundResolution -> (RoundStart | MatchVictory) -> Closed
  ```

  Deadlines use `workspace:GetServerTimeNow()`, so client countdowns match exactly. Disconnects lead to forfeit or auto-play, practice bots use `BotBrain`, and rewards are granted server-side at victory.
* **MatchService** runs every live match from one Heartbeat. Multiple arenas per server are supported.
* **QueueService** owns pads, quick play, invites, practice bots and the "match found" countdown.

## Networking

| Remote | Direction | Purpose |
|---|---|---|
| `QueueRequest` | C→S | Play (mode) / Leave / Practice |
| `InviteRequest`, `InviteResponse` | C→S | duel invites |
| `SelectionRequest` | C→S | Pick index / Reroll / Collection id |
| `AimUpdate` (unreliable), `AimLock` | C→S | aim angle only |
| `TradeRequest` | C→S | Request / Respond / SetItem / Ready / Cancel |
| `StoreRequest` (function) | C→S | OpenCrate / OpenTicket / Equip / RedeemCode / ClaimGroup / BuyGems |
| `PlayerData` | S→C | sanitised profile view |
| `StationState` | S→all | pads, occupants, match summary (hearts above heads) |
| `MatchPublic` | S→viewers | phase changes and round results |
| `MatchPrivate` | S→participant | offers, aim spawn, results |
| `BattleEvent` | S→viewers | batched, sim-timestamped events |
| `BattleSnapshot` (unreliable) | S→viewers | 20 Hz binary snapshots (≤ ~780 bytes) |
| `TradeState`, `InviteReceived`, `RewardPopup`, `Notify`, `LeaderboardData` | S→C | UI state |

**Interest management**: participants plus players within `Game.SpectatorRange` of an arena receive its feed. Late spectators get a full-state event.

**Client sync**: snapshots are interpolated with a 100 ms delay, using a minimum-latency clock-offset estimate. Events wait until the interpolated timeline reaches their `tm`, so VFX line up with the visible collision. Heavy hits add 70 ms of hit-stop, which then catches up smoothly.

## Security rules

* No remote grants currency, items, damage or results. Clients send intents only.
* `Guard` applies per-player token-bucket rate limits to every endpoint. Handler errors are contained.
* All arguments are type- and bounds-checked (`Validate`): finite numbers, integer ranges, id patterns and enum strings.
* State checks:
  * Selection only works in `BallSelection` for that participant. The collection pick requires ownership, and the free pick is limited to once per match.
  * Aim only works in `AimPhase` and only before the lock.
  * Gacha costs are deducted before rolling, inside one non-yielding profile mutation.
* **Trading**: offered items are checked against live inventories. Any change resets both Ready flags. A countdown precedes execution, and execution re-verifies and swaps atomically between two session-locked profiles. Leaving cancels the trade, and busy players cannot trade.
* **Purchases**: receipts are idempotent per `PurchaseId` and only acknowledged after a successful save.

## Persistence

* `ProfileStore` claims a session lock with `UpdateAsync`.
  * A lock from a live server is respected. A stale lock (older than 150 s) is stolen.
  * Each save refreshes the lock and verifies ownership. A lost session kicks the player to prevent duplication.
* Autosave runs every 60 s. Profiles are released on leave, and `BindToClose` releases everyone.
* `Schema.Sanitize` repairs and clamps every field and runs versioned migrations.
* In Studio without API access, an in-memory mock store is used and a warning is printed.

## Performance notes

* One Heartbeat drives all matches. Each simulation step costs O(balls² + entities × balls), with a cap of 140 entities.
* Client effects use pooled emitters and popups, `Debris` for short-lived parts, and no per-frame `FindFirstChild` in hot loops.
* Orbs are BillboardGuis (no physics parts). Entity visuals are anchored, non-colliding, non-queryable parts.
* `StreamingEnabled` is off: the lobby is compact, and arena visuals are client-side.
